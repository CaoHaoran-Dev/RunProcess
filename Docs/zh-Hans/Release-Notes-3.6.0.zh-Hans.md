# RunProcess 3.6.0

> [English](../en/Release-Notes-3.6.0.md) · 简体中文 · [繁體中文](../zh-Hant/Release-Notes-3.6.0.zh-Hant.md)

此前只在预览版提供的远程执行和工作流，现已并入正式版。

---

## 新增

- **远程执行** —— 配对另一台 Mac 后，在同一个命令窗口里把命令发过去执行。配对使用 6 位验证码，通过系统通知送达；已配对的主机也会出现在菜单栏的 Bonjour 发现里。
- **工作流** —— 存放在 `workflows.yml` 里的多行脚本，用短名称触发。它和别名、历史一起参与补全，并在执行前展开。
- **远程访问策略** —— 由被控端按能力逐项决定远程客户端能做什么：执行命令、运行工作流、以 root 执行、修改别名、读取或清除历史、访问文件。命令中出现违禁词会被拒绝。
- **远程快捷指令** —— 为快捷指令和 Siri 提供「运行远程命令」和「搜索远程历史」。
- **帮助新增「远程执行」主题** —— 应用内帮助（`⌘/`）现在覆盖被控端设置、配对、切换主机、权限与重连。

---

## 安全与行为变化

### 远程权限默认全部拒绝

远程控制**默认关闭**；即便打开，**也不会默认允许任何能力**，必须在「设置 → 远程 → 远程权限」里逐项开启。此前的预览版默认全开，对正式版来说过于宽松，因此改为失败即拒绝（fail closed）。在尚未开启任何能力时，远程设置页会显示警告，且所有远程请求都会被拒绝。

### 打开远程控制时才请求通知权限

应用不再在首次启动时索取通知权限。提示会在你开启「允许远程控制」时出现 —— 这是唯一会用到通知的功能（配对码）。若拒绝通知，验证码仍会通过应用内弹窗显示。

### 启用远程控制后，对端需要重新连接

在它的窗口中重新执行一次命令，或打开一个新窗口；之前已经建立的连接不会自动刷新。切换主机则是另一个方向：菜单栏的「远程」子菜单会作用于所有已打开的窗口，而新开的窗口默认在本机执行。

### 远程两端必须同版本

通信协议在不同版本之间并不稳定，请把两台 Mac 一起升级。

---

## 执行相关的修复

- `CommandExecutor` 不再使用全局唯一的「当前任务」。并发执行（两个窗口同时跑 sudo，或快捷指令与窗口并发）不会互相取消，取消范围仅限发起方自己那一次执行。
- 补全面板改为每个窗口一份，不再是全局单例，不会再跟着最后请求的窗口跑。
- 调试日志不再输出用户命令和客户端 token 哈希，逐帧连接追踪只在 Debug 构建输出。

---

## 从源码构建

CI 现在会真正构建两个 scheme 的 **Release** 配置；此前的流程构建的是 Debug，即使 Release 构建失败也可能显示通过。测试仍在 Debug 下运行，因为 `@testable` 需要 `-enable-testing`。

---

## 从预览版升级

两个版本的数据目录相互独立：正式版用 `~/Library/Application Support/RunProcess/`，预览版用 `RunProcess-Beta/`。别名、历史、工作流和已配对主机不会迁移，切换后请**重新配对被控主机**。两个版本可以并存。

---

## 已知问题

- 在 Intel + **Xcode 26.3** 下以 Release 构建 Preview target 时，`swift-frontend` 可能在 SIL 优化阶段间歇性崩溃。重新构建通常即可成功。CI 使用 Xcode 26.5，暂未观察到该问题。
- 应用未做公证；首次启动若被拦截，请到「系统设置 → 隐私与安全性」中允许。
