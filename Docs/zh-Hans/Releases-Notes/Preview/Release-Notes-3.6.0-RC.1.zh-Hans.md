# RunProcess 3.6.0 RC.1

预览通道的候选版本。正式版仍停留在 3.5.0；本次构建是 `RunProcess Preview.app`，使用独立的数据目录。

---

## 本版内容

- **远程执行** —— 配对一台 Mac 后，可以从另一台 Mac 的命令窗口、菜单栏的「远程」子菜单，或快捷指令在它上面执行命令。
- **工作流** —— 存放在 `workflows.yml` 里的多行脚本，用短名称触发。
- **远程访问策略** —— 按能力逐项授权，外加违禁词，全部在被控端校验。
- **配对通知** —— 6 位配对码通过系统通知送达，无法投递时回退为应用内弹窗。
- **远程快捷指令** —— 为 Shortcuts / Siri 提供「运行远程命令」和「搜索远程历史」。

---

## 安装前请留意的行为变化

### 远程权限默认改为「全部拒绝」

此前的预览版中，打开「允许远程控制」就等于默认放行所有能力（执行命令、以 root 执行、改别名、读写历史、访问文件）。从 RC.1 起默认 **一项都不允许**：在被控端的「设置 → 远程 → 远程权限」里显式勾选之前，所有远程请求都会被拒绝。

如果你是升级用户且依赖过旧默认值，请打开该页面重新确认实际需要的能力。在尚未勾选任何一项时，远程设置页会显示警告，且远程命令一律不生效。

### 远程两端必须同版本

预览版之间的通信协议尚不稳定。控制器与被控端需要一起升级到 RC.1。

## 本次候选版的工程质量改进

- **CI 现在会真正构建 Release 配置。** 原工作流的「Release」步骤没有带 `-configuration Release`，实际构建的是 Debug；而且脚本未在出错时中止，构建失败可能被后续成功的步骤掩盖。现在两个 scheme 都会以 Release 构建、以 Debug 测试，覆盖 arm64 与 x86_64。
- `CommandExecutor` 不再使用全局唯一的「当前任务」。并发执行（两个窗口同时跑 sudo，或快捷指令与窗口并发）不会互相取消，取消范围仅限于发起方自己那一次执行。
- 补全面板改为每个窗口一份，不再是全局单例，不会再跟着最后请求的窗口跑。
- 调试日志不再打印用户命令和客户端 token 哈希；逐帧连接追踪只在 Debug 构建输出。

## 已知问题

- **在 Intel + Xcode 26.3 上以 Release 构建 Preview target 时，`swift-frontend` 会间歇性崩溃**：编译器在 SIL 优化阶段（`DeadFunctionAndGlobalElimination` / `objCBridgingOptimization`）以空指针解引用或堆损坏终止。重新构建通常即可成功，事后连续多次 clean rebuild 都通过。CI 使用 Xcode 26.5，暂未观察到该问题。本地 Release 构建若这样失败，请重跑一次。
- 因此，构建 Release 需要一个不会偶发崩溃的工具链。

---

## 安装

1. 解压 `RunProcess-Preview.zip`，把 `RunProcess Preview.app` 移到「应用程序」。
2. 若首次启动被 macOS 拦截，到「系统设置 → 隐私与安全性」里允许。
3. 与正式版一样，本次构建未做公证。

本版数据位于 `~/Library/Application Support/RunProcess-Beta/`。
