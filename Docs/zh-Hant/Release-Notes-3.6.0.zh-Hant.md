# RunProcess 3.6.0

> [English](../en/Release-Notes-3.6.0.md) · [简体中文](../zh-Hans/Release-Notes-3.6.0.zh-Hans.md) · 繁體中文

先前只在預覽版提供的遠端執行和工作流，現已併入正式版。

---

## 新增

- **遠端執行** —— 配對另一台 Mac 後，在同一個指令視窗裡把指令傳過去執行。配對使用 6 位驗證碼，透過系統通知送達；已配對的主機也會出現在選單列的 Bonjour 探索裡。
- **工作流** —— 存放在 `workflows.yml` 裡的多行腳本，用短名稱觸發。它和別名、歷史一起參與補全，並在執行前展開。
- **遠端存取原則** —— 由被控端依能力逐項決定遠端用戶端能做什麼：執行指令、執行工作流、以 root 執行、修改別名、讀取或清除歷史、存取檔案。指令中出現禁用詞會被拒絕。
- **遠端捷徑** —— 為捷徑和 Siri 提供「執行遠端指令」和「搜尋遠端記錄」。
- **輔助說明新增「遠端執行」主題** —— 應用程式內輔助說明（`⌘/`）現在涵蓋被控端設定、配對、切換主機、權限與重新連線。

## 安全與行為變更

### 遠端權限預設全部拒絕

遠端控制**預設關閉**；即使開啟，**也不會預設允許任何能力**，必須在「設定 → 遠端 → 遠端權限」裡逐項開啟。先前的預覽版預設全開，對正式版而言過於寬鬆，因此改為失敗即拒絕（fail closed）。在尚未開啟任何能力時，遠端設定頁會顯示警告，且所有遠端請求都會被拒絕。

### 開啟遠端控制時才要求通知權限

應用程式不再在首次啟動時索取通知權限。提示會在你開啟「允許遠端控制」時出現 —— 這是唯一會用到通知的功能（配對碼）。若拒絕通知，驗證碼仍會透過應用程式內彈窗顯示。

### 啟用遠端控制後，對端需要重新連線

在它的視窗中重新執行一次指令，或開啟一個新視窗；之前已經建立的連線不會自動重新整理。切換主機則是另一個方向：選單列的「遠端」子選單會作用於所有已開啟的視窗，而新開啟的視窗預設在本機執行。

### 遠端兩端必須同版本

通訊協定在不同版本之間並不穩定，請把兩台 Mac 一起升級。

## 執行相關的修正

- `CommandExecutor` 不再使用全域唯一的「目前任務」。並行執行（兩個視窗同時跑 sudo，或捷徑與視窗並行）不會互相取消，取消範圍僅限發起方自己那一次執行。
- 補全面板改為每個視窗一份，不再是全域單例，不會再跟著最後請求的視窗跑。
- 除錯日誌不再輸出使用者指令和用戶端 token 雜湊，逐幀連線追蹤只在 Debug 建置輸出。

---

## 從原始碼建置

CI 現在會真正建置兩個 scheme 的 **Release** 配置；先前的流程建置的是 Debug，即使 Release 建置失敗也可能顯示通過。測試仍在 Debug 下執行，因為 `@testable` 需要 `-enable-testing`。

---

## 從預覽版升級

兩個版本的資料目錄相互獨立：正式版用 `~/Library/Application Support/RunProcess/`，預覽版用 `RunProcess-Beta/`。別名、歷史、工作流和已配對主機不會遷移，切換後請**重新配對被控主機**。兩個版本可以並存。

---

## 已知問題

- 在 Intel + **Xcode 26.3** 下以 Release 建置 Preview target 時，`swift-frontend` 可能在 SIL 最佳化階段間歇性崩潰。重新建置通常即可成功。CI 使用 Xcode 26.5，暫未觀察到此問題。
- 應用程式未做公證；首次啟動若被攔截，請到「系統設定 → 隱私權與安全性」中允許。
