# RunProcess 3.6.0 RC.1

預覽通道的候選版本。正式版仍停留在 3.5.0；本次建置是 `RunProcess Preview.app`，使用獨立的資料目錄。

---

## 本版內容

- **遠端執行** —— 配對一台 Mac 後，可以從另一台 Mac 的指令視窗、選單列的「遠端」子選單，或捷徑在它上面執行指令。
- **工作流** —— 存放在 `workflows.yml` 裡的多行腳本，用短名稱觸發。
- **遠端存取原則** —— 依能力逐項授權，外加禁用詞，全部在被控端驗證。
- **配對通知** —— 6 位配對碼透過系統通知送達，無法投遞時退回為應用程式內彈窗。
- **遠端捷徑** —— 為 Shortcuts / Siri 提供「執行遠端指令」和「搜尋遠端記錄」。

---

## 安裝前請留意的行為變更

### 遠端權限預設改為「全部拒絕」

先前的預覽版中，開啟「允許遠端控制」就等於預設放行所有能力（執行指令、以 root 執行、改別名、讀寫記錄、存取檔案）。從 RC.1 起預設 **一項都不允許**：在被控端的「設定 → 遠端 → 遠端權限」裡明確勾選之前，所有遠端請求都會被拒絕。

如果你是升級使用者且依賴過舊預設值，請開啟該頁面重新確認實際需要的能力。在尚未勾選任何一項時，遠端設定頁會顯示警告，且遠端指令一律無效。

### 遠端兩端必須同版本

預覽版之間的通訊協定尚未穩定。控制器與被控端需要一起升級到 RC.1。

## 本次候選版的工程品質改進

- **CI 現在會真正建置 Release 配置。** 原工作流的「Release」步驟沒有帶 `-configuration Release`，實際建置的是 Debug；而且腳本未在出錯時中止，建置失敗可能被後續成功的步驟掩蓋。現在兩個 scheme 都會以 Release 建置、以 Debug 測試，涵蓋 arm64 與 x86_64。
- `CommandExecutor` 不再使用全域唯一的「目前任務」。並行執行（兩個視窗同時跑 sudo，或捷徑與視窗並行）不會互相取消，取消範圍僅限於發起方自己那一次執行。
- 補全面板改為每個視窗一份，不再是全域單例，不會再跟著最後請求的視窗跑。
- 除錯日誌不再列印使用者指令和用戶端 token 雜湊；逐幀連線追蹤只在 Debug 建置輸出。

## 已知問題

- **在 Intel + Xcode 26.3 上以 Release 建置 Preview target 時，`swift-frontend` 會間歇性崩潰**：編譯器在 SIL 最佳化階段（`DeadFunctionAndGlobalElimination` / `objCBridgingOptimization`）以空指標解引用或堆積損毀終止。重新建置通常即可成功，事後連續多次 clean rebuild 都通過。CI 使用 Xcode 26.5，暫未觀察到此問題。本機 Release 建置若這樣失敗，請重跑一次。
- 因此，建置 Release 需要一個不會偶發崩潰的工具鏈。

## 安裝

1. 解壓縮 `RunProcess-Preview.zip`，把 `RunProcess Preview.app` 移到「應用程式」。
2. 若首次啟動被 macOS 攔截，到「系統設定 → 隱私權與安全性」裡允許。
3. 與正式版一樣，本次建置未做公證。

本版資料位於 `~/Library/Application Support/RunProcess-Beta/`。
